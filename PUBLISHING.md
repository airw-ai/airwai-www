# Publishing — airwai.com

How to create and change pages on Airwai's public marketing site. This is the process doc; `README.md` covers repo layout and `DEPLOY.md` covers one-time setup.

## Golden rules

1. **`src/` is the only source of truth.** Never hand-edit `docs/` — it is generated by `build.py`.
2. **Never push straight to `main`.** Branch, PR, review, merge. Merging `main` is what deploys.
3. **Don't change a shipped page's design without intent.** If a change should be invisible (a copy fix, a new page, tooling), confirm the built output for existing pages is unchanged before you PR.
4. **This repo is world-readable.** Nothing sensitive lands here — see rule 6. Assume every file is publicly searchable on GitHub the moment it merges.
5. **No secrets, ever.** Worker secrets are write-only via `wrangler secret put`. A credential that lands in a commit or in chat is rotated immediately.
6. **No internal-only content in the repo.** That means: no product prices (pricing is ROI-first and delivered in a quote — a public rate card that conflicts with a customer's quote undercuts the deal); no CUI / FOUO / controlled material (it lives outside the repo and loads into KV at runtime from an external path); no internal security-posture / gap registers, insurance status, or unreleased-engagement disclosures. When in doubt, keep it out and load it into KV.

## Make a change

```bash
git checkout main && git pull            # always start from the deployed state
git checkout -b fix/<short-name>
# edit src/<page>.html (and _partials/ only if the change is site-wide, on purpose)
python3 build.py                         # regenerate docs/ locally and eyeball the page
# open docs/<page>/index.html to confirm it renders as intended
git add src/<page>.html                  # commit SOURCE; CI rebuilds docs/ on merge
git commit -m "<what and why>"
git push -u origin HEAD
gh pr create --base main                 # PR → review → merge → auto-deploy
```

- **Commit `src/`, not `docs/`.** CI runs `build.py` and deploys the fresh build, so committing generated `docs/` only adds diff noise and merge conflicts. (See "Conventions" — `docs/` is a build artifact.)
- **A new page** is just a new `src/<name>.html` (or `src/<folder>/<name>.html` for a nested route). `build.py` maps it to `docs/<name>/index.html`. Add nav/footer links in `_partials/` if it should be discoverable.

## Deploy

- **Static site:** `.github/workflows/docs.yml` fires on push to `main`. It runs `python3 build.py` and deploys `docs/` to GitHub Pages (custom domain via Cloudflare). No manual step.
- **Worker (`/api/*`):** the storefront/API is **not** part of the static-site build and is **not** in this public repo (it carries internal config; see rule 6). It is versioned in a private repo and deployed with `wrangler deploy`. Templates and controlled content are loaded into KV from outside the repo.

## Repo map (public)

| Path | What | Deployed by |
|---|---|---|
| `src/` | Page source (body + `@meta`) — **edit here** | `build.py` → Pages |
| `_partials/` | Shared nav / footer / base wrapper (site-wide) | `build.py` → Pages |
| `docs/` | **Generated** output (do not hand-edit) | uploaded to Pages |

The Worker/API, its templates, D1 migrations, and KV loader scripts live in a **private** repo, not here.

## Content discipline (public-facing copy)

- **Facts and lawful routes only.** Describe what the offer is and the lawful ways to buy it (direct award, cooperative vehicle, GSA/SEWP, sole-source). **Do not tell a public agency how to stay under its board/bid thresholds or skip an RFP** — that reads as coaching them around their own oversight. Defer the procurement path and the accounting/booking treatment to the buyer's purchasing office and auditors.
- **ROI, not price** (rule 6). No dollar rate card on the site.
- **PCI/compliance claims:** "FAA-accepted," never "certified" for anything Airwai isn't. Say "in progress" for attestations not yet held.
- **Brand v2** tokens/logo per the Design System; the AIRWAI wordmark is never improvised or recolored.
- **No AI attribution.** Site content and commits are Airwai's work; do not credit an assistant.
- **"Department of War," not "Warfighter"** in DoW-facing copy.
- **Deep links:** `/pricing#airports|authorities|dot|federal|aec` select and scroll to a buy-path lane; clicking a lane updates the URL so a lane-specific link is shareable.

## Conventions

- **`docs/` is a build artifact.** CI rebuilds it on every deploy, so it does not need to be committed. Recommended follow-up: `git rm -r --cached docs/` and add `docs/` to `.gitignore` (done in a dedicated PR, since it is a large diff). Until then, if you do commit `docs/`, rebuild it in the same commit as the `src/` change so the two never drift.
- **Legal pages** (`src/legal/*`) are reviewed by counsel before they go live. Do not publish a new legal page (AUP, ToS, disclaimer) without that review.
- **Design-canvas working files** belong in the design-system repo, not here (git-ignored via `_design-canvas/`).
